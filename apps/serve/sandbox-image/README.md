# atlas-sandbox

The published toolchain image for Atlas sandboxes, destined for `ghcr.io/<owner>/atlas-sandbox`: `node:22-trixie-slim` (trixie is required — its git 2.47 understands the scoped `safe.directory` wildcards the harness injects, bookworm's 2.39 ignores them) plus git, ripgrep, gpg, the docker CLI and compose plugin, plus a baked dockerd behind a lazy `/usr/local/bin/docker` shim that starts the daemon via sudo on first use (Vercel sandboxes get docker-in-docker; the local docker sandbox passes through to its mounted host socket), mise-managed node/python/bun with idiomatic version files (`.nvmrc`, `.python-version`, `.bun-version`, `package.json`) enabled so repos auto-select their runtimes, corepack with yarn/pnpm/npm pre-seeded, headless chromium baked in, and the `@playwright/cli` agent CLI pinned on `PATH` with its own chrome-for-testing build in the same `/opt/playwright` browsers path (`PLAYWRIGHT_MCP_BROWSER=chromium` points bare `playwright-cli open` at it, since the CLI otherwise defaults to a Google Chrome channel the image does not carry) — so creating a sandbox takes seconds instead of a per-create apt/install dance. bun inside is mise-managed: upgrade it with `mise upgrade bun`, never `bun upgrade`, which desyncs the binary from mise's recorded version. Build locally with `docker build -t atlas-sandbox:dev packages/harness/sandbox-image` and verify with `packages/harness/sandbox-image/smoke.sh atlas-sandbox:dev`; published tags are `sha-<7>` and floating `latest` per merge, with semver tags cut by the release-on-main workflow (`.github/workflows/release.yml`) that versions `bin/atlas`. mise's `trusted_config_paths` covers exactly `/Users` and `/home` because sandboxes bind-mount worktrees at their identical host paths, which live under a macOS or Linux home; per-tree `mise trust` cannot be pre-run for host paths the image cannot know, exec-path commands (`mise run`/`install`/`exec`) auto-trust the active config anyway, so the setting exists for `hook-env` — and paranoid mode is deliberately off because content-hash re-trust would break on every edit of a mounted file.
