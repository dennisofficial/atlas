# Decisions (slice 3, PR 3)

- **No allowlist** (operator, 2026-11-03: "make it public, it's ~3 people"). The session routes are open to every signed-in user; each procedure checks the caller owns the session. `V2_USER_IDS` is gone.
- **No `v2` prefix on names** (operator, 2026-11-03: at cutover v1 is deleted and v2 becomes the regular code). Drop the prefix wherever the plain name is free; keep it only where it collides with a live v1 name (`V2Event`/`V2Body`, the Prisma `V2*` models and the `v2` Postgres schema), renamed at cutover. Applied in #1787. Env: `DAEMON_SECRET` (Atlas Cloud project secret, generated 2026-11-03), `AGENT_HOST_TOKEN`. tRPC: `sessions.*`, `agentHost.*`. Redis: `atlas:session-wake`, `atlas:session-live:<id>`. Task id `reconcile-holders`. Later slices use the new names.

- **A v2 session opens a v2-only thread page** (operator, 2026-11-03). In atlas-web/mac, choosing a v2 session routes to a page whose transcript, right pane and every other read uses only `v2.*` procedures. v1 pages and v1 procedures never accept a v2 id. At cutover the routing switch is deleted and the v2 page becomes the only page. PR 3 consequence: `v2.*` read procedures are designed to grow into everything that page needs (events, status, later live/views/blobs). No v1 procedure gains a v2 branch. The page itself is slice 5.
- **Remote call keys are per daemon operation.** A tool call's scope key is `${runId}:${callId}` (hashed to `${runId}:h<16 hex of sha256(callId)>` if it fails `callKeySchema`). Each daemon operation inside the tool takes `${scopeKey}.${n}`, numbered in call order. Re-dispatching the same call replays the same keys, so the daemon attaches to or returns each one. Re-dispatch _is_ crash recovery for daemon-backed tools. Reason: the core ports (`ProcessPort.spawn`, `FileSystemPort.*`) carry no call identity, and deterministic sub-keys make a replay idempotent without changing any port.
- **The call scope travels by AsyncLocalStorage**, set by a host-side `ToolDispatcher` wrapper around the agent's dispatcher. Ports read it. Outside a scope (setup, clone), keys are `host-<uuid>`.
- **Row 5 is applied once, in `RemoteCalls.invoke`.** The call scope carries `dispatchedBootId`, set by the record adapter through `markDispatched({ bootId })` when it appends, or on a replay drops, the call's `tool-dispatched`. Before sending `run`, if that bootId differs from the daemon's current one, invoke asks core `recoverCall` (answer `never-seen`): read-only reruns, anything else fails as interrupted with nothing sent. So a holder never needs its own boot comparison: crash recovery for daemon tools is re-dispatch.
- **Crashed host-side tools keep v1's rule.** On claim the holder runs agent's `settleCrashedCalls` with an `effectOf` that reports daemon-backed tools as `Read`, because their replay is safe through the rule above, and host tools with their real effect.
- **A second `tool-dispatched` for a call that already has one is dropped by the host record adapter**, and the original `bootId` is used for `recoverCall`. This keeps "every tool-dispatched ends with exactly one tool-result".
- **The inbox is consumed in the same append as its message.** The host intake emits `user-said` with `requestId: 'inbox:<inboxId>'`. The host record adapter prepends `input-consumed { inboxId }` to the append that carries it, so one transaction consumes the entry and records the message.
- **Lease time is the database's clock, read after the lock.** `ControlTx.now()` returns `clock_timestamp()` in Postgres, not `now()`: `now()` is fixed at transaction start, so an append that waited on the thread lock across expiry would pass with an expired lease (review of #1766). Memory returns its injected clock. `ControlPlane` reads it once per transaction, **after** the row lock the decision depends on: the thread lock for an append, and the lease row locked `FOR UPDATE` for a lease mutation.
- **Reconcile finds sessions through `V2Lease.wantsHolder`.** `revoke` takes `wantsHolder`: a drain/handoff revoke sets it true, an idle release sets it false, and `grant` clears it. `sessionsNeedingHolder` = lease not live AND (holderId not null OR wantsHolder OR an unconsumed inbox entry exists).
- **Redis channel names live in `packages/protocol/src/bus.ts`** (`WAKE_CHANNEL = 'atlas:session-wake'`, `sessionLiveChannel(sessionId)`, `wakeMessageSchema`). API, host and trigger all import them.
- **`V2Session` gains `userId`, `projectId`, `title?`, `mainThreadId`.** The migration deletes pre-existing `v2` rows (spike/test leftovers; no v2 session has ever been created through an API).
- **The generated AppRouter may import `@dltech/atlas-protocol`** (the session API schemas live there per spec point 1). `packages/api-router` gains the dependency and its allowlist spec gains the specifier.
- **The host does not depend on harness.** Daemon-backed ports implement core's `ProcessPort` / `FileSystemPort` / `AgentFileSystemPort`. `apps/agent-host` composes harness's model adapters and builtin tools over them.
