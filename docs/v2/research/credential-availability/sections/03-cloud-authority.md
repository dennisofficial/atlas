# 03 — Durable credential availability at request time

## Delivered behavior and chosen seam

Planning only against `eeee3e7effbd6112d6aec42232d164b69d6ebfa0`; no application changes or test execution in this pass. Depends on slices01–02's normalized failure, pure transition function, per-attempt wrapper and local authority. This section adopts the locked cross-slice contract in `context/contracts.md` verbatim: NormalizedProviderFailure from01, the CredentialAvailabilityPort shape (inspect/admit/promoteProbe/complete/control), ERequestCompletion terminal enum, AvailabilitySnapshot/AdmissionPermit/Admission and the exact request lifecycle defined there. Cloud-only DTOs below are transport bindings of those exact types, not a competing core port or lifecycle. Where02's text and contracts.md disagree, contracts.md wins.

**Choose one small, uncached admission mutation immediately before EVERY actual provider attempt for API-owned credentials while authenticated.** Follow it with a bounded outcome report. A permit is for one attempt, not a turn. PostgreSQL owns automatic availability and the exclusive half-open probe. This is two independent PRs03a/03b below, not one all-or-nothing OAuth rewrite. The same harness wrapper runs local, serve, main, children and utility calls. Neither the turn driver nor a UI owns enforcement. Successful streams and tools already executing continue; the next model attempt is gated.

Direct RPC versus bounded cache: direct RPC adds one control-plane round trip per provider attempt but needs no push bus, cache invalidation protocol or stale-positive allowance. Model latency dominates for this one-user product. A bounded positive cache would knowingly admit more calls after a pause, need a separate probe path and introduce outage grace rules; **reject that design in this slice**. Account/config caches remain for their existing purposes, but cannot answer admission. This is credential availability, not a distributed concurrency/rate limiter: healthy attempts are not serialized for their duration, and there is no token bucket, global provider circuit, routing graph or alternate model selection.

## Exact policy/interface proposal for integration with slices01–02

Implement contracts.md's exact five-method port: `inspect({target})`, `admit({target})`, `promoteProbe({permit}): Promise<AdmissionPermit | null>`, `complete({permit,result})`, `control({key,expectedGeneration,action})`, with the terminal `ERequestCompletion` enum (`Succeeded` | `Failed{failure}` | `Cancelled`) from contracts.md. `promoteProbe` is the nonterminal, exactly-once probe→ordinary handoff at first meaningful output: it atomically validates the credential+route epoch vector and replacement identity, sets claimed scopes Ready (generation increments once), and returns the NEW ordinary permit carrying post-promotion fences and a NEW opaque receipt — so a later mid-stream `complete(Failed)` (including quota delivered as an SSE error part after first output) opens its current scope through ordinary Failed completion against the post-promotion epoch. A final healthy finish completes Succeeded. Stale/replaced/superseded promotion returns null: the already-successful output is preserved and forwarded, newer authority state is untouched, and terminal completion of the old permit is ignored — the stream is never aborted for a failed/lost promotion or lease expiry. Terminal Cancelled is its own arm, neither success nor provider failure; exactly one terminal complete is attempted per permit and it is idempotent. Core generation maps to DB epoch. The following NEW types are Cloud HTTP DTOs only; use real E-prefixed enums for their discriminants.

```ts
type CloudCredentialFence = {
  accountId: AccountId
  secretVersion: number
  grant?: { connectionId: string; authorizationId: string }
}
type AdmissionRequest = {
  fence: CloudCredentialFence
  route: { providerId: string; modelId: string }
}
type CloudAdmissionDto =
  | {
      type: ECloudAdmission.Admitted
      receipt: string
      serverAt: string
      startWithinMs: number
      probeDeadlineMs?: number
      snapshots: AvailabilitySnapshot[]
    }
  | { type: ECloudAdmission.Blocked; blocked: ModelBlocked }
  | { type: ECloudAdmission.StaleCredential; current: CloudCredentialFence }
  | { type: ECloudAdmission.AuthorityUnavailable; retryable: true }
type CloudPromoteOutput =
  | {
      type: ECloudPromote.Promoted
      receipt: string
      permit: AdmissionPermit
      snapshots: AvailabilitySnapshot[]
    }
  | { type: ECloudPromote.Superseded; snapshots: AvailabilitySnapshot[] }
type CloudCompleteInput = { receipt: string; result: RequestCompletion }
```

CloudPromoteOutput maps to promoteProbe's return: `Promoted` carries the new ordinary permit (adapter returns it); `Superseded` maps to null. Terminal complete replies carry only the current snapshots.

Mapping to slice02's revision prerequisite: `CredentialRevision={authority:Cloud, issuer:<canonical API origin>, version:String(secretVersion)}` exactly as slice02 stamps it, 02 alone has a `version:'unknown'` older-API compatibility path without authoritative revision safety.03a+ MUST reject that incomplete fence for API-key authority, and03b+ likewise for Cloud-owned OAuth; neither may silently downgrade to02's compatibility admission.03 does not reintroduce tuple-parsed versions or any HMAC/Runtime scaffold. `CredentialTarget.accountId` is the canonical API accountId. The OAuth grant pair (`connectionId`,`authorizationId`) is NOT part of `CredentialRevision`; it is API-internal receipt material in 03b, compared against `AgentAccount.oauthConnectionId`/`oauthAuthorizationId`, and a reconnect already increments `secretVersion`, which is what fences old receipts. Credential scope maps to the account row; Route maps to the exact account/model row. DB available/cooldown/action-required/probe-in-flight map to Ready/CoolingDown/Blocked/Probing; Paused is the manual overlay. Snapshot.key/generation/failure/observedAt/eligibleAt/probeExpiresAt retain slice02's shape; add OPTIONAL `controlVersion` and `serverAt` for Cloud controls. resetAt stays in the normalized failure. AdmissionPermit.id is the current opaque receipt (replaced by the receipt carried on a Promoted reply after a promoteProbe handoff), target/fences come from the returned snapshots, probe is true iff a lease was claimed. StaleCredential is handled by the adapter's single reacquire; AuthorityUnavailable is a typed Delivery/Network control-plane exception, not a persisted provider kind. Dates are ISO UTC strings on wire, epoch-ms inputs to core, Date at DB adapter. Scope keys are API-encoded `account` or `model:${JSON.stringify([providerId,modelId])}`; never caller storage keys.

Pure core's single admission/transition function consumes a snapshot, serverNowMs, normalized outcome, observed epochs and optional lease fence; returns a decision/conditional patch. It performs no clock/network/DB/crypto I/O. API validates the normalized kind/scope/provider tuple and selects scope through the same pure transition policy; it does NOT re-normalize a reduced status/message into a second classifier. Harness retries, stream handling and wait outcomes remain slices01–02's feature logic. API implements atomic persistence of those decisions; no generic state-machine framework.

Credential types gain optional authority identity `{ url, userId, fence: CloudCredentialFence }`, copied from acquisition to `Credential`, per-attempt context and failure observation. For remote accounts, canonical fence.accountId is the API account's id. A local alias id may remain `Credential.accountId` for local selection/UI; never use that alias for the API fence. Persist `secretVersion` on API account DTOs and optional `authorityIdentity` on core `Account`/vault. New cloud acquisition MUST yield a complete fence; absent fields are not revision zero. Host-only accounts use slice02's local revision scheme, never send fabricated API ids. Old stored vault entries remain readable and are upgraded by authenticated acquisition, not by guessing.

## Exact freshness, budgets and baseline semantics

- Every real doGenerate/doStream, SDK retry, OAuth second attempt and stream restart crosses slice02's admitted-model/admission-credential-port seam with contracts.md's stream wiring (initial rejection → terminal complete Failed; first meaningful output → `promoteProbe` handoff; end/error → terminal complete Succeeded/Failed; abort → terminal complete Cancelled). Resolve account plus authoritative revision from metadata, admit BEFORE raw read can mint/refresh, then revalidate the actual returned credential fence. Known block costs zero refresh exchanges. Cached reads dispatch under that one RPC. If a legitimate raw acquisition/mint exceeds its5s permit start window, cancel/settle that permit and return a freshness wait without provider dispatch; keep the newly cached access for the next explicitly requested resume, not an immediate second mint or a re-admit that would contend with its own live probe. No duplicate wrapper. No admission for pure `supportedUrls`, catalogue reads, or every streamed token. Disable hidden SDK retry layers not already handled by slice01. Stream success is recorded by terminal completion only, never by receipt of HTTP headers.
- Admission: 2,500ms request timeout, no automatic HTTP retry; 1,000ms DB statement timeout and250ms lock timeout (SET LOCAL). Control-plane gate budget8,000ms includes at most ONE uncached reread/re-admit after StaleCredential (maximum two admission RPCs); cancel any obsolete owned permit before reacquiring. Expired start window settles/waits instead of reacquiring its own probe. Legitimate OAuth mint retains a separate abortable30,000ms maximum; total acquisition bound38s. No mint/provider call inside admission handler/transaction. Second stale/expired result returns recoverable acquisition failure, never an unbounded loop.
- A healthy permit authorizes dispatch for 5,000ms from DB-issued serverAt. Harness uses elapsed monotonic time since the admission RPC START, subtracting round-trip time; it never trusts local wall-clock agreement. No dispatch after that deadline; return recoverable wait rather than silently reuse a permit. Permits are never cached, shared or reused. Manual pause can race a request already admitted in that finite interval; it cannot retract an already-admitted/upstream request. This is not instantaneous revocation of secrets already delivered to a runtime.
- Half-open: durable lease45,000ms; SAME30,000ms abortable START deadline as slice02, not a whole-stream timeout. First meaningful output disarms the start deadline BEFORE any promote await, calls `promoteProbe` (2,500ms timeout), then forwards the buffered first output with original backpressure. A Promoted reply converts the lease to ordinary and clears the barrier in one mutation; the wrapper swaps to the returned ordinary permit and the final SSE quota/error completes under the NEW receipt/fences. No lease heartbeat. Superseded (stale fences): the stream settles normally and its later terminal completion mutates nothing. Lost ACK: the wrapper does not issue a second model request; the original probe receipt resolves that exact promotion against the retained `lastPromotedProbeId`/post-promotion vector when the terminal complete arrives; never abort the healthy stream just to satisfy the lease. Extra15s covers promote/settlement. Crashed probes reclaim on demand; the guarantee is one valid authoritative lease, not upstream cancellation of a disconnected former holder.
- Outcome reporting (nonterminal promoteProbe and terminal complete): synchronous local transition first, 2,500ms RPC timeout, await before allowing another attempt; no fire-and-forget durability claim. Receipt window24h; promoteProbe additionally requires its unexpired45s lease, while the ordinary receipt it issues has its own24h window against exact post-promotion epochs. A late ordinary terminal success never changes eligibility. A failure after the report window stays locally blocked but cannot mutate Cloud from an expired receipt. No background report retries and no per-token reporting; an operator/session resume can recheck authority. Log sanitized transport failure, not credential invalidity.
- API timeout/5xx/DB outage: deny NEW API-owned attempts with `AuthorityUnavailable`, not `ActionRequired`, and no use of cached positive availability. 401/403 from Atlas means control-plane authentication/configuration failure, never proof of bad provider credentials. No periodic wake/retry loop: surface slices02/04's waiting reason; retry on explicit recheck/resume or the next independently requested step. No automatic cross-provider fallback.
- Provider hard quota with a validated provider reset uses EXACT resetAt. Unknown hard-quota reset and proven revoked auth use ActionRequired until operator recheck/replacement. Persist only confirmed credential faults and ModelDenied route blocks in Cloud in this slice. Temporary429/network/5xx/stall remain slice02's runtime-local counters/cooldowns with its exact constants (1s initial, 3 failures/30s window, doubling to60s, never earlier than a provider hint), not a generic shared provider circuit. A failed/aborted/timed-out CLOUD recovery probe with no durable hard evidence reopens its already-durable scope for a concrete 30,000ms nextProbeAt (NOT a claimed provider resetAt). Reject malformed/past reset instants rather than infer midnight; do not persist provider billing-scope guesses.

## Atomic database protocol (not read-then-write without a transaction)

Use Prisma 8 `db.transaction(async tx => ...)`, native ORM for basic reads, parameterized `tx.raw.sql` plus `.affectedCount().build()` / `.returnsRow(...).build()` for locks/CAS. Existing executable examples are `prisma-oauth-connection.store.ts:64–78,99–111` and `sessions/pod-snapshot.ts:22–29`. There is no `@prisma/client`, `$transaction`, P2002, `migrate dev`, or Prisma7 shim.

03a operations lock owned AgentAccount, then account scope, then model scope;03b adds linked OauthConnection FIRST when applicable, preserving the SAME total order (fixed order, not arbitrary input order). No provider call inside the transaction. Ordering is resolve account/grant metadata → admit against that exact fence → raw acquisition/refresh outside the transaction → revalidate actual fence and monotonic dispatch deadline → provider dispatch. Known-blocked credentials perform zero refresh/mint exchanges. Re-read connection after its lock during admission so a reconnect cannot slip past cached metadata; a changed post-acquisition fence cancels the obsolete permit and uses the single bounded reacquire/re-admit path. Bounded lock failure is AuthorityUnavailable, not a retry spin. Parent account lock deliberately serializes short admission/report decisions for one account, not provider inference.

Admission transaction:

```sql
SELECT id, "secretVersion", "availabilityControlVersion", "manuallyPausedAt",
       "oauthConnectionId", "oauthAuthorizationId"
FROM "AgentAccount" WHERE id = $account AND "userId" = $verifiedUser FOR UPDATE;
INSERT INTO "CredentialAvailability" ("accountId", "scopeKey", "secretVersion", state)
VALUES ($account, $scope, $revision, 'available') ON CONFLICT ("accountId", "scopeKey") DO NOTHING;
SELECT * FROM "CredentialAvailability"
WHERE "accountId" = $account AND "scopeKey" IN ($accountScope,$modelScope)
ORDER BY "scopeKey" FOR UPDATE;
UPDATE "CredentialAvailability" SET state='probe-in-flight', "probeId"=$newUuid,
 "probePrincipal"=$verifiedPrincipal, "probeExpiresAt"=$dbNow + interval '45 seconds',
 epoch=epoch+1, "updatedAt"=$dbNow
WHERE "accountId"=$account AND "scopeKey"=$scope AND "secretVersion"=$revision
 AND epoch=$observedEpoch
 AND ((state='cooldown' AND "nextProbeAt" <= $dbNow)
   OR (state='probe-in-flight' AND "probeExpiresAt" <= $dbNow));
```

Read DB time once per transaction (`transaction_timestamp()`), use it in all patches and receipt. Verify route provider matches owned account; compare full revision/grant; return stale before admitting or mutating automatic state. Upsert both needed scopes under parent lock. Manual pause or ActionRequired denies. Unexpired lease or not-yet-due cooldown denies. For all due scopes a single attempt claims each in the SAME transaction, with one attempt UUID; if ANY scope denies, claim NONE. Exactly one competing transaction wins. Claim increments target epoch; receipt contains AFTER-claim epochs plus current controlVersion. Available scopes need no write. The SQL above is executed for each due scope only after the whole decision is known. Actual code must insert required timestamps/defaults consistently with the emitted contract. For lost-promotion-ACK resolution, each claimed scope row additionally retains `lastPromotedProbeId String?` plus the post-promotion epoch vector (`promotedEpoch Int?`) until the next barrier/control/replacement changes it; the original authenticated probe receipt may resolve ONLY that exact promotion to its deterministic post-promotion vector when a terminal report follows a lost promotion reply. Any changed row/probe id/epoch invalidates it. These two nullable columns ride migration A (03a); they are lifecycle bookkeeping, not an execution checkpoint or general receipt database.

Report/control/replacement transaction CAS:

```sql
UPDATE "CredentialAvailability" AS s SET state=$nextState, "reasonCode"=$reason,
 "resetAt"=$reset, "nextProbeAt"=$nextProbe, "probeId"=NULL,
 "probePrincipal"=NULL, "probeExpiresAt"=NULL, epoch=s.epoch+1,
 "observedAt"=$dbNow, "updatedAt"=$dbNow
FROM "AgentAccount" AS a
WHERE a.id=s."accountId" AND a.id=$receiptAccount AND a."userId"=$verifiedUser
 AND a."secretVersion"=$receiptRevision
 AND a."availabilityControlVersion"=$receiptControlVersion
 AND a."manuallyPausedAt" IS NULL
 AND s."scopeKey"=$derivedScope AND s."secretVersion"=$receiptRevision
 AND s.epoch=$receiptScopeEpoch;
UPDATE "AgentAccount" SET "manuallyPausedAt"=$pauseOrNull,
 "availabilityControlVersion"="availabilityControlVersion"+1
WHERE id=$account AND "userId"=$verifiedUser AND "secretVersion"=$expectedRevision
 AND "availabilityControlVersion"=$expectedControlVersion;
```

Before that report UPDATE, verify the current OAuth connection + authorizationId still equal the receipt and, for probe settlement, additionally require `s.probeId=$receiptProbeId AND s.probePrincipal=$principal AND s.probeExpiresAt>$dbNow`. Receipt also carries account-scope epoch; check it even for model-scoped settlement so an older model success cannot erase a newer account failure. Use `.affectedCount()` and require exactly one; zero means stale/duplicate, a successful no-op response with current snapshot. Do not retry it against a newer revision. Epoch fence, not client timestamps, defines ordering. First accepted conflicting observation wins; another call admitted at that older epoch cannot override it, even if its delayed failure looks more severe. A new probe/attempt supplies new evidence.

Ordinary terminal successes NEVER clear cooldown/action-required/manual pause. The promoteProbe mutation validates both receipt epochs, controlVersion, credential (and grant in03b), owned probeId/principal and unexpired lease; sets ALL claimed scopes available with epoch+1, clears leases, stamps `lastPromotedProbeId`/`promotedEpoch`, and seals a NEW ordinary receipt bound to the post-promotion vector and the same principal/attempt identity — all in the SAME transaction, no partial handoff. It returns Promoted with the new permit. Superseded (null) on stale/replaced/superseded rows. Idempotent ACK-loss resolution: the original probe receipt resolves only to the deterministic post-promotion vector when the retained `lastPromotedProbeId` matches and the rows are still at that vector; any newer barrier/control/replacement/reclaim invalidates it. The wrapper retains the new permit for the stream's final result; a stale probe receipt can never settle it. A later SSE quota/failure after promotion opens the proper scope under the NEW fences via ordinary Failed completion; older successes lose CAS. Terminal ordinary success is a no-op on state; duplicate terminal failure loses epoch CAS. No inference is restarted or replayed by the handoff. A newer failure, manual control, replacement or probe reclaim invalidates old success. A normal terminal failure while a probe exists has an older epoch and is ignored; a duplicate report cannot affect its successor. Expired lease never becomes available by time alone: the next admission reclaims it as one new probe. A terminal failure writes ONLY the derived proven fault scope, not both scopes — except a confirmed account-wide failure observed by a model-scoped probe, which opens the account scope under the same receipt's account epoch and releases its claimed model lease without making the account available. Zero/failed CAS rolls back the entire patch set.

Owner recheck sets hard-blocked automatic scopes to cooldown with nextProbeAt=dbNow (or provider-evidenced temporary not-before if later), resetAt unchanged, clears leases, increments epochs/controlVersion; it is eligibility for ONE test, not proof of success. It does not unpause a manually paused account. Resume clears only manual overlay, increments controlVersion and invalidates leases; pre-existing automatic ActionRequired remains until explicit recheck/replacement. Controls require expected secretVersion; a concurrent replacement returns Conflict and a refreshed snapshot, not an operation on the replacement.
