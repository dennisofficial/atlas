# Incident 2026-11-01: a session lost about 560 events of visible state to a seq-466 fork

Part of the evidence for [v2](../README.md). Code anchors are `file:line` as read on 2026-11-01
and may have drifted. Statements marked _(inferred)_ are conclusions drawn from the evidence, not
observed directly.

Session `ses_ff5d7e3b-14b4-40dc-b644-35d8787ec2f9` ("Atlas worktree and services setup"), main
thread `brn_b88ee197-e9a4-48ba-a0fa-fed33a151cd4`, running in a cloud pod on Vercel Sandbox. All
times are UTC.

## Symptom

The agent cut a branch, committed twice, pushed and opened a pull request, which was merged at
19:25. Neither the web sidebar nor the Details panel showed the PR, and the branch showed the
project's base branch (`staging`) instead of the agent's branch.

## Evidence

- Postgres `Event` rows for the thread stop at seq 466 (17:27:01). `Thread.head` is 466, but
  `activityAt` is 19:33 and `rev` is 1798.
- The pod's transcript (`<atlas home>/sessions/<sid>/threads/<tid>.events.jsonl`) has head 1025:
  `checkout-observed` for the new branch at seq 658 (18:35:09) and `pull-request-linked` at
  seq 891 (18:57:21).
- The serve log shows the first `serve.event-flush-conflict seq=466 durableHead=465` at
  17:27:05.710, then 336 of them through 19:33:32. At 17:27:05.933,
  `serve.pull-failed: cannot mirror a delta starting at seq 466: the local head is already 466`.
  At 18:23:49, `serve.park-refused reason=unflushed`. The log file is not committed.
- Seq 466 diverges between the two stores:

  | Store          | Event                                                              | Time         | Written by                                                                                     |
  | -------------- | ------------------------------------------------------------------ | ------------ | ---------------------------------------------------------------------------------------------- |
  | API (Postgres) | `user-said` "I'm stuck at this, maybe hmr issue?", run `run_5d14…` | 17:27:01.797 | `appendUserSaid`, `apps/api/src/api/cloud/sandbox-provisioning/thread-messages.service.ts:140` |
  | Pod (JSONL)    | `user-said` "Lets see whats going on here", run `run_6a11…`        | 17:27:05.440 | the pod's local append                                                                         |

- `GithubSubscription` rows for the PR persisted (18:57, 19:21) and the runtime checkpoint
  persisted (19:36). Those use separate write paths, so the session looked alive.

## Root cause

Two independent seq allocators write one log: the API's send path and the pod's local log. A
message arrived over each path within 4 s across a detach/attach. Both minted seq 466.

- `applyPodEvents` (`apps/api/src/api/platform/sandboxes/pod-events.ts:54-66`) correctly refuses
  the divergent row with a 409.
- The flusher (`apps/serve/src/serve-event-flush.ts:64-72`) logs the conflict and returns false.
  Its `rebase` is wired only to rewind and compaction (`apps/serve/src/serve-history-mirror.ts`),
  so nothing heals an append fork. Every later flush hit the same wall.
- All UI state derived from persisted events (PR links, branch, worktree) froze at seq 465.
  Branch fell back to the project base branch
  (`apps/api/src/api/platform/sessions/thread-checkout-fallback.ts:11-28`, see
  [control-plane-state](control-plane-state.md)).

## Observed but unrelated

- `RATE_LIMIT_PER_MINUTE` was unset in production, so the default of 100/min per procedure per IP
  applied (`apps/api/src/_core/config/env/sections/runtime.ts:12`). `githubSubscriptions.subscribe`
  returned 429 repeatedly from 18:56 to 19:21.
- A reviewer sub-agent failed 46 times with an OpenRouter 401 "Missing Authentication header".
- The pod's `sessions/<sid>/meta.json` held `"pullRequests": null`, another copy of state that
  never updates.

## Why it matters beyond the bug

[Rule 2 of docs/architecture.md](../../architecture.md) ("One record") holds inside one process.
Pods broke it: the pod JSONL and Postgres are two records joined by best-effort replication with
no ownership protocol. Fixing the one seam would leave the others. See
[pod-side-state](pod-side-state.md), [control-plane-state](control-plane-state.md) and
[wire-surface](wire-surface.md) for the full set.

The v1 stopgap (the pod reconciles an append fork) is described in
[architecture.md §8](../architecture.md).
