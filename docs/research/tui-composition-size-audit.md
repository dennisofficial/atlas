Audited on 2026-10-01 against `4fd55d02ed0258fd607254682d1def6071bcaed0`, before the composition extraction.

## Scope and measurement

Enumerated tracked paths with `git ls-files -z -- apps packages`. Counted physical lines, including blank lines, comments, and final unterminated lines. Scanned 3,265 code, style, and schema files; checked extensionless executables and grammar assets separately. Excluded dependency/build outputs, binary assets, maps, JSON data/configuration, documentation, and frozen `deprecated/` code. Handwritten `apps/tui/src/build/` source remained included.

159 handwritten files exceeded the repository's 300-line maximum: 38 production files, 109 tests, four fixtures/helpers, and eight scripts/prototypes/spikes. One additional generated file exceeded the limit. TUI composition had seven oversized production files and 25 oversized tests/helpers.

These counts describe the baseline, not a standing exemption or a claim that this PR fixes the entire inventory.

## Composition extraction

The external interface stays `App` and its existing cloud helper exports. `app.tsx` is reduced from 2,342 to 150 lines; the workspace composition is 298 lines, and every changed implementation file is below 300. `App` retains cloud attachment ownership, reload coalescing, keyed workspace remounts, and same-thread native-buffer draft handoff.

The workspace composes focused modules for session/draft bindings, models and account views, conversation navigation, composer interactions, location controls, exit/restart lifetime, notices, naming, layout, keyboard arbitration, and presentation. There is no universal workspace context or replacement giant hook. Existing `useCloudLift`, `useThreadRouter`, `useThreadView`, and harness relocation interfaces remain the operational seams.

Keyboard arbitration deliberately retains overlay order, porous input flags, menu-first interception, and sidebar escape precedence. Submission retains image settlement, native-buffer reads, queued command handling, and refusal restoration. Background wait timing remains above child transcript mounts. Location controls bind the existing harness operations rather than implementing another relocation state machine.

The failed cloud-descend ownership incident is separate behavioral work. This extraction does not repair live sessions or change relocation commitment/recovery semantics.

## Recommended follow-up slices

- `use-conversation.ts`: isolate settled-command draining, message delivery, and adoption/workspace metadata behind their existing intake and thread interfaces. Keep the event log authoritative; do not create a mirrored conversation state store.
- `use-turn-driver.ts`: separate remote observation from commit/run/settle and confirmed history actions. Keep settlement and interrupt identity coherent across local and remote adapters.
- `use-accounts.ts`: separate device-login lifetime from terminal key/paste translation. Preserve cancellation and account refresh ownership.
- `remote-delta-channel.ts`: give replay, frame interpretation, and reconnection/socket generation distinct implementations while retaining one public channel interface.
- `settings/registry.ts`: group declarative definitions by domain and preserve IDs and ordered aggregation. This has lower behavioral risk than the lifecycle modules.
- Large specs: split by scenario families and share focused fixtures, rather than moving the same giant fake or hiding setup in a broad helper.

Each follow-up should be independently reviewable and verified through its existing public interface. Reaching 300 lines by compressing formatting or arbitrary slicing does not improve module depth or locality.
