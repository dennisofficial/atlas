# v1 retirement — client inventory (apps/mac, apps/web, apps/mobile, packages/ui-native)

Repo: `/atlas/workspaces/atlas/.atlas/worktrees/dennis/v1-retirement-spec` at `main` @ `78e4d7a9e`.
Read-only survey. No file in the repo was modified.

## Headline findings

1. **The Mac local-pods host is not wired into the shipped app.** `apps/mac/src/desktop-host/index.ts:33-54`
   builds `createDesktopHost({...})` without a `pods` option, and `apps/mac/src/host/index.ts:112-115` only
   creates the pods handler when `pods !== undefined`. `/desktop/pods` and `/desktop/capabilities` therefore
   404 in the real app, `useDesktop()` resolves `present: false`
   (`apps/web/src/features/desktop/use-desktop.ts:34-56`), and every local-pod code path in the web renderer
   is unreachable today. Deleting the local-pods host removes no working capability.
2. **Harness reaches `apps/mac` through exactly 10 production files**: the 11 sources under
   `src/host/pods/` plus `src/host/auth/token-store.ts:2`. Plus one build script,
   `apps/mac/scripts/pack-host.ts:4,76`, which imports harness source directly.
3. **Push, notification clicks, deep links and sign-in do not touch harness or the pods host**, with one
   type-only exception: `src/host/apns-routes.ts:3` imports `TrackNotificationInput` from
   `@dltech/atlas-wire`.
4. **`apps/web/src/features/threads` is the v1 thread UI, but it is also the v2 presentation layer.** 80 files
   inside it are imported by `features/sessions/*`, `features/shell/*`, `features/settings/*` and
   `features/routines/*`. It must be **split and moved, not deleted** — see B2.
5. **The sidebar still merges a v1 live-thread stream with the v2 session list**
   (`apps/web/src/features/shell/use-shell-entries.ts:16-38`). Deleting v1 requires replacing the sidebar's
   primary source, not just dropping a page.
6. `apps/mobile` and `packages/ui-native` contain **no v1-only code**. Mobile imports only
   `@dltech/atlas-wire` (types) and `@dltech/atlas-wire/web`.
