# Runtime/capture evidence for advisory Code Quality

Planning only. Read plan.md and decisions.md first. Repository evidence is /atlas/workspace at supplied snapshot 293d199c; origin/main is unavailable here. No source changes, installs, tests, session-data reads or credential reads. Recommendations below are implementation defaults for main to accept/reject, not final contracts.

## Executive recommendation

Use successful ToolOutcome.fileChanges transient typed metadata captured inside the three tools' existing FileWriteGuardPort.underLock callbacks. Reuse edit/multi_edit's raw source and final replacement strings; add one best-effort before-content read to write, inside its lock, never in a BeforeTool hook. Dispatch a bounded QualityReviewPort after invoke succeeds and after the lock is released. Return result + review record + optional finite nudge as drafts through the existing turn append/publishing chain. Fold finding state from the current durable events, never from a separately mutated map. Initial supported operations: write/edit/multi_edit, UTF-8 TS/JS/TSX/JSX, identifiable bounded scopes. Shell/background/services/MCP/external edits and parser uncertainty are explicit noncoverage.

Preserve the new code-quality-reviewed event in SURVIVES_SUMMARY; retain it as bookkeeping, not prompt content. A review record must be self-contained because its referenced tool call/result can disappear in destructive summary. On rewind let records/nudges above the cut disappear normally; files are NOT restored. Re-evaluate actual captured content after rewind rather than trusting historical finding status to describe today's disk.

### Minimal suggested signatures/changes

- Core: new CapturedFileChange type with requested absolute path, before: string | null, after: string (null means absent, not empty), and enough workspace/backend provenance to map an identity across relocation. Add `fileChanges?: readonly CapturedFileChange[] | undefined` only to ToolOutcome's ok:true branch (tool.ts:68-74). Do not add raw source to output, ToolDeclaration or durable model messages.
- Include explicit capture availability/skip status if complete content cannot be read/decoded within a bound. Unknown-before must NEVER be encoded as before:null. If main chooses no skip union in CapturedFileChange, omit fileChanges and emit/log a separate capture-unavailable reason. Advisory capture must not introduce a new permission failure for write that otherwise could commit.
- Under-lock edits: add metadata to both edit helper success returns and multi_edit aggregate success. For write, stat -> best-effort read of existing regular file -> rename -> attach metadata. Avoid duplicate pre-hook reads. Do not perform model calls, AST scans, durable logging or expensive disk artifact creation while holding the lock.
- Strings are exact text evidence only for valid UTF-8. Local readFile decodes UTF-8 (local-filesystem.ts:26-27); Docker readFile uses TextDecoder (docker-filesystem.ts:100-110). Invalid UTF-8 loses byte identity. Gate unsupported/binary files; use readBytes+fatal UTF-8 decode for write's before-read if byte validity matters. Keep BOM/CRLF/trailing-newline distinctions in raw text. Supplied after strings with unpaired surrogates are UTF-8-encoded by the file ports; either reject quality capture for these strings or capture their actual UTF-8 roundtrip, not a purported byte-exact original JS string.
- Suggested harness port: `review(args: { call: ToolCall; events: readonly Event[]; result: Extract<ToolOutcome, { ok: true }>; projectDirectory: string; signal: AbortSignal }): Promise<readonly EventDraft[]>`. Core may own the pure declaration; harness owns implementation/registration. Dispatcher constructor gains optional review dependency, and shared container injects it (create-harness-container.ts:240-249). Main owns exact event/policy definitions.
- Dispatch branch: after successful invoke and only when captured changes exist, run bounded reviewer outside invokeTool's catch, fallback to fault/skipped review bookkeeping or no advisory drafts; preserve original result no matter review failure. Return one ordered batch: tool-result, code-quality-reviewed, optional nudge, normal AfterTool drafts (order relative to existing hooks is main's contract). No direct append inside review and no mutable ledger update before durable append.
- IMPORTANT stale-ledger seam: settle-pending.ts:68 reads events once for ALL pending calls; :84-94 passes that same snapshot even after earlier serial calls append. A reviewer folding this input can emit duplicate nudges within one step. Refresh events before each serial write dispatch (e.g. await deps.log.read before settleOne; pending call list remains snapshotted), or otherwise supply freshly read current events for quality. Do not introduce a second history store.

## Feature-sized hazards for ownership/order

Capture, parser adapter and durable event schema/fold are independent slices but dispatcher depends on all three. Event schema + SURVIVES_SUMMARY + fold semantics must land together; otherwise a destructive summary silently erases dedupe. Fresh events in settlePending and publication containment are concrete integration seams, not optional speculative infrastructure. Shell coverage, cross-thread global dedupe, realpath/backend-aware locks, OS-wide file transactions, automatic restoration on rewind, and background asynchronous reviewer scheduling are separate larger features. No such expansion is required for the bounded advisory first release.
