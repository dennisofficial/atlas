## Recommendation

Following main's contract draft, create one development-only root **`evals/`** workspace (`@dltech/atlas-evals`), explicitly adding `"evals"` to root workspace members, shared by AI features, not a production Code Quality submodule. Pin **`evalite: "0.19.0"`**, not a floating range or `beta`. Use Evalite for scheduling, task/scorer registration and raw result export; add a small Atlas artifact/coverage adapter, not another competing evaluator runner. Keep core zod-only and shipped harness free of evaluator dependencies. First-release Code Quality adapter imports **pure quality question/state preparation + the exact JevDecisionClient leaf module**, not the harness barrel or composition root. This leaf is Node-safe after transpilation in the no-network probe below. Make a full Node Evalite smoke the release gate; a Bun subprocess is only a fallback for future features that actually require Bun, not initial required architecture.

Suggested initial toolchain pins: `vitest: "4.0.1"`, `vite: "6.4.1"` as dev dependencies alongside Evalite. These are consciously selected compatible major/floor pins, not claims to be the newest Vitest/Vite releases. Evalite's published stable package uses Vitest runner/utils 4.x; Atlas API currently uses 3.2.x, so do not reuse API's dependency accidentally. Vite 6.4.1 supports repository Node 22.13.1; letting Vitest choose Vite 7 can require a newer Node patch. Revalidate transitive resolution and run the smoke gate before committing any chosen lockfile.

Current registry tags: `latest=0.19.0`, `beta=1.0.0-beta.16`. Stable and beta have different artifact/API shapes. Beta has useful optional SQLite and a non-exiting `run-once` mode, but still exports the latest full run, changes `evals/results` to `suites/evals`, defaults cache on, automatically loads env files, and its optional AI integration peer is `ai ^6`, not Atlas's AI SDK 7. Those are not reasons to adopt a beta for this first slice. Stable can do one-shot output without a server and is adequate with explicit safety checks.

### Before/after reconstruction matrix

- **`write` success**: `/atlas/workspace/packages/harness/src/tools/builtin/write.ts:19-22,67-75` captures full requested after content in input, output resolved path/created/bytes. `created=true` supplies observed absence of the prior file at stat time. - **Diff limits**: `/atlas/workspace/packages/harness/src/tools/builtin/unified-diff.ts:3,119-147,150-174` uses three context lines and EOF markers. A hunk is not necessarily the surrounding function/class/module. Ordinary edit diffs are LF semantic evidence, not exact original byte snapshots. With an authenticated full baseline, apply and verify hunks to reconstruct both scope states; without one, mark diff-only or partial-scope and exclude from the primary SRP golden set.
- **Read output**: `/atlas/workspace/packages/harness/src/tools/builtin/read.ts:25-29,83-90,106-119,254-282` stores line-numbered model text plus `{path,lines,truncated}`. Default 2,000 lines, 256KiB, 2,000 chars per line; CRs stripped and final empty line discarded. A complete unclipped read can provide semantic full text, not trustworthy exact original line endings/final-newline bytes. Partial reads may support a full changed scope only if independently proven; do not infer a complete file merely by concatenating arbitrary reads.
- **Read-state cache**: `/atlas/workspace/packages/harness/src/files/read-state.ts:6-25` is in-memory metadata/digest, not durable before contents. It cannot supply historic missing text.
- **Shell/external changes**: bash, Git checkouts/commits, other threads, editor writes, missing results, interrupt windows and location transitions can break read->edit chains. Prefer explicitly exported base Git objects/full text or prospective captured pairs. A nearby complete read plus a matching patch is an observationally supported reconstruction, not proof nobody else mutated unseen portions. Record that confidence and do not advertise universally byte-exact history.

For usable reconstruction, require: successful settlement; resolved target path; tool/version semantics; full changed semantic scope on both sides; deterministic patch application/preimage match; hashes of derived before/after; provenance and line-normalization mode. Paths are repo-relative in curated cases. New-file after text may be strong evidence; overwrite before state often is not. Binary and non-source writes are not initial policy cases.

### One-shot trustworthy artifact protocol

1. Allocate unique invocation UUID and a **new exclusive run directory**. Write manifest before execution: code commit, feature/policy/prompt/questions/schema/grader versions, dataset hash/version, selected case IDs/order, variants, expected trial count, provider/model identity, sanitized endpoint identifier, concurrency, timeout/retry settings, mode and start time. No secret material. Reject existing output directory; do not delete past runs.
2. Use fresh in-memory Evalite storage per Node child, outputPath `<run>/evalite.raw.json`; disable server. Capture process exit, stderr/stdout and per-task diagnostics into that directory. Stable imports still bring the SQLite dependency even with in-memory storage; smoke its availability rather than pretending the package is native-free.
3. Task input retains case/trial/variant/invocation IDs for artifact matching, but adapter passes **only model-facing input** to production policy. Expected and curator rationale never cross that boundary. Prefer explicit dataset expansion with `trialCount=1` so trial identity is durable in input/output; alternatively native trialCount requires normalized ordinal mapping because raw export drops trialIndex. No provider/decision/task caches when measuring repeats/performance.
4. Treat raw artifact as optional on crash. Missing/truncated/stale/malformed JSON, no fresh run, missing cases, extra cases, duplicate case-trial-variant, running statuses, `only`/skip/empty data, mismatched expected/schema/versions, unexpected scorer coverage, process failures or invalid finite scores are **run-integrity errors**, not model quality. Validate planned cardinality, not a vague full-run flag. Persist explicit planned/skipped/completed/error counts even if raw results omit them.
5. Normalized `results.jsonl` includes validated actual output or execution error, raw answer reference, case/trial/variant, scorer values/differences, request/preparation/grading/total timings, retry count, abort status, model/prompt/context identity. `summary.json` includes integrity, errors, coverage, per-policy/slice confusion counts, accuracy and latency; `summary.md` is compact with failed case IDs and expected->actual differences plus artifact paths. Mark invocation complete only after atomic summary finalization. Preserve partial diagnostics on failure.
6. Wrapper exit codes proposed: 0 integrity complete and configured quality gate met; 1 completed quality regression; 2 infrastructure/integrity/config failure. Check child status too; never reuse a JSON file from a preceding invocation or infer success from stdout/high mean. No universal initial model-quality threshold before baseline calibration.

## Dataset contract and bounded curation deliverables

Generic versioned case envelope: `schemaVersion, id, featureId, input, expected, tags, provenance, review`. Input/expected are JSON data validated by feature-owned zod schemas; framework does not prescribe an SRP-shaped global schema. Dataset manifest records feature input/output schema versions, policy/rubric versions, content hash, cases file, split and counts. Feature registration owns production adapter, deterministic scorers and dataset reducers. Cross-case metrics cannot be replaced by averaging arbitrary scorer means.

SRP input specialization: repo-relative path/language, before/after semantic scopes (null before for creation, null after for scope deletion, never null for unavailable capture), scope identity/range/kind, actual normalized diff, bounded relevant dependency context and capture completeness. Expected specialization distinguishes **before condition**, **after condition**, **edit impact** (introduced/worsened/unchanged/improved/resolved), required bounded answers and intended advisory disposition. Insufficient-context/ambiguous cases have explicit expected abstention or are quarantined; do not secretly turn uncertainty into clean code. Do not compare generated prose or finding random IDs.

Provenance: pseudonymous source corpus/group, owning thread/run/event+call occurrence, source/tool/build versions, original export hashes, repo commit/base blob when available, reconstruction method (captured-pair/Git-baseline+patch/full-read+patch/diff-only), normalized-before/after hashes, scope completeness, redaction transform version. Keep private source IDs/path mapping in a restricted provenance sidecar, not public prompts. Golden review: rubric version, provisional label generator/version, independent verifier record, disagreement/resolution and accepted status. No model-under-test output may establish the expected label for its own evaluation.

## Deterministic quality vs performance metrics

- Deterministic per-case grades compare stable bounded expected/actual answer IDs and field tuples. Validate shape first. Required key absent/invalid choice/probability is an interpretation fault, not a benign false result. Set-like finding evidence uses canonical sorting/matching, not literal UUID comparison. Option-order/question-order metamorphic variants should preserve semantic answers.
- Report TP/FP/TN/FN, precision/recall/F1, clean-negative FPR, balanced accuracy, per-impact/scope slice counts and abstention/decided coverage. Define which expected fields constitute a positive. Precision with zero predicted positives and other zero denominators is null with counts, not 1. Ambiguous labels and runtime failures are separate populations. Provide successful-decision-only efficacy and planned-run error/coverage alongside it; never quietly drop errors/skips from denominators.
- For probability outputs only when meaningful/present: Brier/calibration bins and sample count; do not invent comparable confidence for all answer forms. Repeats quantify per-case instability/flip rate/score distribution, not independent unique examples; report unique case count and trials separately. Holdout used for final comparison, not every tuning turn.
- Performance: capture preparation/request/interpretation duration with a monotonic clock inside the Node task, end-to-end and child start/import overhead separately, grading separately, p50/p95 with sample counts, error/timeout rates, attempts/retries, concurrency/provider/model/cache conditions. Cold/warm trials separated; no timing from historical turn ledger used as policy-call baseline. Same frozen dataset/config for variants. Small N p95 is descriptive, not a calibrated SLA.
